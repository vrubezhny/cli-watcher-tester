# cli-watcher-tester

Standalone tester for the
[CLI Watcher](https://github.com/eclipse-che/che-machine-exec/tree/main/timeout/cli-watcher.go)
in [eclipse-che/che-machine-exec](https://github.com/eclipse-che/che-machine-exec).

The watcher normally lives inside a DevWorkspace pod, where it prevents
the workspace from idling when user-initiated CLI processes are active.
This tester runs the same code on a developer machine, logging each
activity tick to stdout instead of stopping a workspace. The full
Docker image build / DevWorkspace deploy cycle is skipped.

## Goals

- Exercise `che-machine-exec/timeout/cli-watcher.go` in seconds, without
  building a che-machine-exec image, packaging it into a DevWorkspace,
  and waiting for the workspace to start.
- Validate behavior changes (env-var configuration, defaults, command
  detection) locally before sending a PR upstream.
- Inspect what the watcher actually sees in `/proc` for a given process
  (with `--verbose=true`).

## Layout

```
cli-watcher-tester/
├── main.go                          # flag parsing, env-var setup, wiring, main loop
├── internal/
│   ├── timeout/
│   │   └── cli-watcher.go           # NOT in git; regenerated by `make build` from $CHE_MACHINE_EXEC_DIR/timeout/cli-watcher.go
│   └── tick/
│       └── tick.go                  # stub: logs activity ticks
├── Makefile
├── go.mod / go.sum
├── README.md
└── .noidle.example
```

Note: `internal/timeout/cli-watcher.go` is gitignored. It is regenerated
on every `make build` (via `make sync`, which copies from
`$CHE_MACHINE_EXEC_DIR/timeout/cli-watcher.go`). The repo therefore
does not build from a clean clone unless `che-machine-exec` is available
at `$CHE_MACHINE_EXEC_DIR` (defaults to `../che-machine-exec`).

## Prerequisites

- Go 1.25.7 or newer
- A sibling `che-machine-exec/` checkout at the same level as this
  directory (or set `CHE_MACHINE_EXEC_DIR` to point at it)
- Linux with `/proc` mounted (the watcher scans `/proc/[pid]/comm`,
  `/proc/[pid]/stat`, etc.)

## Build

```bash
make build
```

This runs `make sync` first, which copies
`$CHE_MACHINE_EXEC_DIR/timeout/cli-watcher.go` (default
`../che-machine-exec`) into `internal/timeout/cli-watcher.go`, then
compiles. The output binary lives at `bin/cli-watcher-tester`.

`make sync` is a hard precondition: if `CHE_MACHINE_EXEC_DIR` is unset
or the file is missing, the build fails with a clear error.

To use a non-default source location:

```bash
make build CHE_MACHINE_EXEC_DIR=/path/to/che-machine-exec
```

## Run

### Defaults (no flags)

```bash
make run
```

This respects the watcher's own defaults. Since the watcher's
`CLI_ACTIVITY_TRACKER_ENABLED` defaults to `false`, no ticks will fire
and the process will idle forever. Useful for verifying the watcher
boots cleanly.

### With flags

```bash
make run ARGS="--enabled=true --logLevel=debug"
```

`ARGS` is passed through to the binary verbatim. Any number of flags
can be combined.

### Convenience targets

```bash
make run-enabled                 # --enabled=true, otherwise watcher's defaults
make run-verbose                 # --enabled=true --verbose=true (watcher activity logs at info; tester stays at info)
make run-fulllog                 # --enabled=true --verbose=true --logLevel=debug (everything noisy)
make run-verbose ARGS="--checkPeriod=15s"
```

### Direct binary

```bash
./bin/cli-watcher-tester --enabled=true --logLevel=debug
```

## Flags

| Flag | Default | Maps to | Notes |
|---|---|---|---|
| `--idleTimeout` | `30m` | (passed to `NewCliWatcher`) | Mirrors che-machine-exec's default. Use `-1` to disable. |
| `--logLevel` | `info` | (sets logrus level) | Independent of `--verbose`. |
| `--enabled` | `""` | `CLI_ACTIVITY_TRACKER_ENABLED` | Empty → watcher's default (`false`). |
| `--checkPeriod` | `""` | `CLI_ACTIVITY_TRACKER_CHECK_PERIOD` | Empty → adaptive default. |
| `--activityWindow` | `""` | `CLI_ACTIVITY_TRACKER_ACTIVITY_WINDOW` | Empty → adaptive default. |
| `--gracePeriod` | `""` | `CLI_ACTIVITY_TRACKER_GRACE_PERIOD` | Empty → adaptive default. |
| `--maxProcessAge` | `""` | `CLI_ACTIVITY_TRACKER_MAX_PROCESS_AGE` | Empty → 6h default. |
| `--verbose` | `""` | `CLI_ACTIVITY_TRACKER_VERBOSE` | Promotes activity-detection logs to info level. |
| `--config` | `""` | `CLI_ACTIVITY_TRACKER_CONFIG` | Path to a `.noidle` file. Empty → upward search. |

Empty flag values mean "do not set the env var". This is intentional:
the watcher is the source of truth for its own defaults, and the tester
just exposes them as override knobs.

## Example session

```bash
$ make run-verbose ARGS="--config=$(pwd)/.noidle.example"
INFO tester: CLI_ACTIVITY_TRACKER_ENABLED = "true" (from --enabled)
INFO tester: CLI_ACTIVITY_TRACKER_CONFIG = "/.../cli-watcher-tester/.noidle.example" (from --config)
...
# In another terminal on the same machine:
$ opencode
# Watcher detects opencode and logs:
INFO [tick #1] Reporting activity tick at 2026-08-26T14:32:01Z | uptime=12s, idleTimeout=30m0s, logLevel=info, env={CLI_ACTIVITY_TRACKER_CONFIG=..., CLI_ACTIVITY_TRACKER_ENABLED=true, CLI_ACTIVITY_TRACKER_VERBOSE=true}
INFO CLI Watcher: Detected CLI command: opencode — reporting activity tick
```

## Sync workflow

`make sync` re-copies the watcher source. Run it explicitly when you
want to refresh without rebuilding:

```bash
make sync
```

`make build` runs sync automatically, so the binary always tests the
latest `che-machine-exec/timeout/cli-watcher.go`.

## Relationship to che-machine-exec

- No changes are made to `che-machine-exec/`.
- The synced `cli-watcher.go` keeps its original EPL-2.0 header, but is **not committed** — it is regenerated from che-machine-exec on every build.
- Other files in this repo also carry the EPL-2.0 header; the tester
  exists to support che-machine-exec development, not as standalone
  software.
